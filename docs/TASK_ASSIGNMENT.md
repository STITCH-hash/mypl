本项目按 4 人团队协作设计，暂时使用成员 A/B/C/D 作为占位名称，不写具体真实姓名。当前阶段以 Text2SQL 最小闭环为最高优先级，RAG 能力作为第二阶段逐步接入。

## 3. 协作要求

| 规则 | 说明 |
| --- | --- |
| 每个人都要提交代码或文档 | 不要最后集中到一个人提交，避免贡献记录不清晰，也方便定位问题。 |
| Text2SQL 最小闭环优先级最高 | 先让自然语言问题能够生成 SQL、执行并展示结果，再扩展复杂能力。 |
| RAG 是第二阶段 | 不要一开始抢主线，先准备文档结构和接口预留即可。 |
| 股票数据先落本地库 | 使用 AkShare 采集约 30 支 A 股的基础信息、最近 1 年日行情和最新行情快照，写入 SQLite 后再由 Text2SQL 查询。 |
| API Key 通过 `.env` 管理 | 不允许把 API Key、密钥、`.env`、缓存、虚拟环境和数据库临时文件提交到 Git。 |
| 分支要小而清晰 | 一个分支尽量只做一类修改，例如后端接口、前端页面、RAG 检索或文档更新。 |
| 提交信息要可读 | 使用类似 `feat: add text2sql query api`、`docs: add dataset design` 的提交信息。 |
